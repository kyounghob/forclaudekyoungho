# ETF 교육 콘텐츠 개인화 추천 시스템

인공지능과추천시스템 중간보고서(`docs/report/ETF_Education_Midterm_Submission.docx`)의 추천 시스템과 실험 코드다.
추천 대상은 ETF 교육 단원 66개(22개 주제 × 3수준, 선수 관계 80개)이며, 특정 ETF의 매수·매도나 투자 적합성은 판단하지 않는다.

## 설치

Python 3.11 이상이 필요하다.

```bash
python -m pip install -r requirements.txt        # 전체(API·테스트·torch 포함)
python -m pip install -r requirements-core.txt   # 학습·평가만
python -m pip install -r requirements-web.txt    # 웹 서비스 실행(torch 없이. torch로 학습한 번들도 읽는다)
```

## 보고서 수치 재현

```bash
python scripts/reproduce_report.py
```

seed 42와 20261023에서 모의 학습자 15,000명 자료를 각각 학습하고, 평가 스크립트와 MF·MLP 비교·생성기 민감도까지 실행한다.
2코어 PC에서 약 9분 걸린다(`--no-extensions`를 주면 MF·MLP·민감도를 빼고 약 3분). torch는 필요 없다.
학습 번들과 전체 결과는 `runs/`에, 보고서와 대응하는 요약은 `results/`에 저장된다.

개별 명령:

```bash
python -m etfrec train --n 15000 --seed 42 --out runs/seed42 --no-neural --prereq-policy required --operational-policy PurposeStageRule
python scripts/purpose_stage_evaluation.py --bundle runs/seed42 --out runs/purpose_stage_seed42
python scripts/goal_stage_evaluation.py --bundle runs/seed42 --out runs/goal_stage_seed42
python scripts/diagnosis_recheck.py --bundle runs/seed42 --out runs/diagnosis
python -m etfrec recommend --bundle runs/seed42 --user 1 --k 5
python -m etfrec serve --bundle runs/seed42 --host 127.0.0.1 --port 8000    # 브라우저에서 http://127.0.0.1:8000
```

`bundle.pkl`은 pickle 파일이므로 직접 학습해 만든 번들만 불러온다.

## 운영 정책: 목적 단계 규칙

```
운영 점수 = 5×정규화 전체 인기 + 3×관심 + 2×수준 일치 + 1×모바일·짧은 콘텐츠 + 2×목적 친화도 + 2×로드맵 단계
```

- 전체 인기는 후보 행별 최소–최대 정규화 값이다(모두 같으면 0). 관심·수준·기기 신호는 0 또는 1, 목적 친화도는 0~1이다.
- 로드맵 단계 점수는 현재 단계에서 학습 가능한 단원 1, 후속 단계에서 가능한 단원 0.7, 잠긴 단원 0.4, 로드맵 밖 0이다.
- 연령·소득·성별은 운영 점수에 쓰지 않는다.
- 모든 기법에 같은 후처리를 적용한다. 이미 통과한 단원과 현재 수준보다 두 단계 이상 높은 단원은 제외하고, 한 단계 위 단원은 최대 1개, 미이수 선수가 있는 단원은 제외하며, 최대 5개를 표시한다.
- 비교 기법(전체 인기, 행동 집단 인기, 콘텐츠 기반, 순수 사용자 CF, 아이템 CF, 검증 선택 규칙)은 비신경망 설정 1,747개를 2주차 검증 NDCG로 탐색해 정하고 3주차에 평가한다. 목적 단계 규칙은 검증으로 고르지 않은 고정 설계값이다.

- 검증 선택 규칙은 연령대·소득분위 집단 인기를 기준 점수로 쓰고 로드맵 단계 항이 없다. seed 42 설정에는 목적 항도 없다.

- 정합률은 점수에 쓰는 로드맵을 기준으로 하므로 교육 효과가 아니라 로드맵과의 일관성을 나타낸다. 모의 데이터 생성기도 목적 친화도를 쓰므로 NDCG 차이는 생성 가정의 영향을 받는다.

## MF·MLP 비교와 생성기 민감도 (보고서 표 9, 4.4절)

```bash
python scripts/reproduce_extensions.py      # 이 부분만 다시 실행: 약 6분, 결과는 results/extensions/
```

**MF·MLP 동일 조건 비교.** MF(ALS, Hu 외 2008), MF(BPR, Rendle 외 2009), MLP(9주차 구조: 임베딩 8 → 은닉 16, 목표 정렬 쌍을 BPR로 학습)를 torch 없이 NumPy로 학습하고, 표 9와 같은 후보·수준·선수 필터·정답으로 평가했다. 설정은 다른 비교군처럼 2주차 검증 NDCG@5로 골랐다.

| 방법 | NDCG@5 seed 42 / 새 seed | 정합률: 공통 기초 이수 가정 seed 42 / 새 seed |
| --- | --- | --- |
| 목적 단계 규칙(운영안) | 0.103070 / 0.122274 | 53.3% / 51.0% |
| 전체 인기 | 0.100642 / 0.117224 | 39.0% / 31.5% |
| MF(ALS) | 0.099291 / 0.117096 | 31.0% / 29.9% |
| MF(BPR) | 0.099231 / 0.117004 | 28.0% / 29.6% |
| MLP | 0.098814 / 0.117326 | 30.1% / 33.9% |

- 운영안과 MF·MLP의 NDCG@5 차이는 +0.0038~+0.0053이고, 두 seed 모두 대응 부트스트랩 95% 구간이 0을 포함하지 않는다.
- 검증에서 고른 MF는 저차원(ALS k=2, BPR k=4)이었다. 단원 66개·사용자당 관측 약 5개인 자료에서 잠재요인 개인화가 인기 이상의 정보를 거의 더하지 못한다는 뜻으로 해석한다.

**생성기 목적 효과 민감도(seed 42).** 생성기의 goal_effect만 0, 0.8(기본), 1.6으로 바꿔 같은 절차를 반복했다.

| goal_effect | 운영안 NDCG@5(순위) | 전체 인기 NDCG@5(순위) | 운영안 − 전체 인기 [95% 구간] | 공통 기초 이수 가정 정합률 운영안 / 전체 인기 |
| --- | --- | --- | --- | --- |
| 0 | 0.088108 (2위) | 0.084644 (7위) | +0.0035 [+0.0015, +0.0054] | 52.6% / 39.2% |
| 0.8 | 0.103070 (2위) | 0.100642 (4위) | +0.0024 [+0.0004, +0.0042] | 53.3% / 39.0% |
| 1.6 | 0.107329 (2위) | 0.100535 (6위) | +0.0068 [+0.0049, +0.0086] | 53.7% / 38.7% |

- 생성기가 목적을 쓰지 않아도 운영안의 NDCG는 전체 인기보다 높았다. 차이의 크기는 생성 가정에 따라 달라진다.
- 1위는 세 조건 모두 인구통계 집단 인기를 쓰는 검증 선택 규칙이다. 생성기가 인구통계 효과를 넣어 자료를 만들기 때문으로 보인다. 운영안은 인구통계 배제 요건 때문에 이 규칙을 쓰지 않는다.
- 정합률은 로드맵 기준이라 생성기 설정과 거의 무관하다.

## 자동 운영 루프

운영 정책을 사람이 고정해 두는 대신, 매주 새 기록으로 다시 학습·선정하고 **검증 게이트를 모두 통과할 때만** 교체하는 루프다(`etfrec/ops/`).
교체 기준은 `etfrec/purpose_policy.py`의 `replacement_rule`을 그대로 판정 코드로 옮긴 것이다.

1. **탐색 칸과 노출 확률**: `/api/serve`는 앞 k−1칸을 운영 순위 그대로 두고 마지막 칸만 확률 ε(기본 0.1)로 다른 적격 단원으로 바꾼다. 탐색 후보는 가드레일·한 단계 위 상한을 이미 통과한 단원뿐이다. 보인 단원마다 포함 확률(앞 칸 1, 마지막 칸 1−ε 또는 ε·q)을 `logs/impressions/week=NNNN.jsonl`에 남긴다. 같은 요청 번호는 같은 결과를 내므로 다시 계산해 확인할 수 있다. 학습 반응은 `/api/feedback`으로 `logs/feedback/`에 쌓인다. 화면의 미리보기·what-if(`/api/recommend`)는 탐색도 기록도 하지 않는다.
2. **주 1회 재학습·재선정**(`ops run-week`): 그 주까지의 기록만으로 w−1주·w주 스냅샷의 특징·신호를 다시 만든다. 후보는 현재 정책, 선언 정책, 가중치 변형 486개, 목적·로드맵 항이 있는 기존 설정이다. 이 가운데 자격 있는 것을 w−1주 NDCG@5로 비교해 도전 정책 하나를 고른다. `--full-retrain`을 주면 표준 학습 파이프라인으로 기준 번들도 새로 학습한다.
3. **검증 게이트**: 선정에 쓰지 않은 w주 자료로 현재 정책과 도전 정책을 비교하고, 아래 기준을 모두 통과해야 교체한다.
4. **교체 이력**: 모든 판정(교체·유지·후보 없음·되돌림·건너뜀·동결)과 그 근거를 `history.jsonl`에 남긴다. 각 줄은 앞 줄의 해시를 품고 있어, 중간 줄을 고치면 `ops history --verify`가 찾아낸다. 주간 보고서는 `reports/week=NNNN.md`·`.json`에 남는다.

| 게이트 기준 | 통과 조건 |
| --- | --- |
| NDCG 향상 | 도전 − 현재 ≥ 0.005, 사용자 단위 짝 부트스트랩 95% 하한 > 0 |
| 현재 단계 정합률 | 도전 ≥ 현재 − 1%p (비열등) |
| 선수 위반 | 0 |
| 자격 | 연령·소득·성별 미사용, 목적·로드맵 항 가중치 ≥ 1, `r:pref` 미사용 |
| 심화 노출 격차 | 같은 변수 안 최대 격차 ≤ 5%p, 또는 현재 정책 이하 |
| 최소 표본 | 확인 주 평가 사용자 ≥ 200 |
| 냉각·동결 | 교체 다음 주는 다시 교체하지 않음, 동결 중에는 교체하지 않음 |
| OPE 비열등 | 탐색 기록으로 추정한 요청당 성공 수 차이의 95% 하한 ≥ −10% × 현재 정책 추정치. 도전 정책만의 단원이 탐색으로 20번 이상 보였을 때만 판정에 쓴다(`require_ope`로 필수화 가능) |

그 밖의 안전장치:
- **자동 되돌리기**: 교체 다음 주에 새 정책의 NDCG가 이전 정책보다 0.005 넘게 떨어지고 구간 상한도 0보다 작으면 되돌린다. 선수 위반이 생겨도 되돌린다.
- **수동 조작**: `ops rollback`(수동 되돌리기), `ops freeze`(교체 동결)
- **중복 실행 방지**: 이미 결정한 주는 다시 판정하지 않는다(`--force` 제외). 동시 실행은 잠금 파일로 막는다.
- **자료 무결성**: 쓴 자료의 sha256을 남긴다.
- **기록 정책 일치도 점검**: 일치도가 0.95 미만이면 OPE를 판정에 쓰지 않는다.
- **보존 기간**: `ops prune --keep-weeks N`으로 오래된 기록을 지운다.
- **서빙 갱신**: 결정 뒤 w주 기록까지 반영한 w+1주 서빙 번들을 만든다. 실행 중인 서버는 등록부 변경을 감지해 재시작 없이 새 정책을 쓴다.

```bash
python -m etfrec ops simulate --ops-dir runs/ops_sim --n 3000 --weeks 8    # 합성 세계에서 서빙→반응→주간 작업 반복
python -m etfrec ops init --ops-dir runs/ops --bundle runs/seed42 --epsilon 0.1
python -m etfrec serve --ops-dir runs/ops                                    # /api/serve·/api/feedback·/api/ops/status
python -m etfrec ops run-week --ops-dir runs/ops --data DIR                  # 주 1회. cron 예: 30 3 * * 1 (매주 월요일 03:30)
python -m etfrec ops status|history --verify|freeze --reason ...|rollback --reason ...|prune --keep-weeks 12 --ops-dir runs/ops
```

모의 실행(학습자 3,000명, 8주, seed 42, 약 30초)에서는 3~7주 모두 선언 정책을 유지했다.
- **3~5주**: 도전 정책이 NDCG 향상 기준을 넘지 못했다(5주는 정합률 비열등도 미달).
- **6~7주**: NDCG는 높였지만 정합률이 떨어져(7주 +0.0072 [+0.0027, +0.012], 정합률 58.0% → 56.0%) 비열등 기준에서 막혔다.
- **OPE**: 현재 정책의 OPE 추정치는 같은 주 전체 통과 기록으로 계산한 실제 값과 매주 0.002 이내로 맞았다(예: 0.2039 vs 0.2033).
- **탐색 비율**: 실제로 탐색한 요청은 노출의 약 4%였다. 선수 조건 때문에 후보가 5개 이하인 학습자는 탐색할 단원이 없기 때문이다.

한계:
- 합성 세계의 행동은 추천과 무관하게 생성되므로, 모의 실행은 기록·추정·판정 절차를 점검할 뿐 추천이 학습을 바꾸는 효과는 담지 않는다.
- OPE는 보상이 함께 보인 단원과 위치에 따라 달라지지 않는다는 가정에 기댄다.
- `serve --public` 없이 띄우면 운영 API에 인증이 없다(로컬 개발용). 외부에 열 때는 아래 공개 모드를 쓴다.

## 웹 서비스로 운영하기

`serve --public`은 실제 사용자가 가입해서 쓰는 학습자 화면을 첫 화면(`/`)으로 연다. 기존 화면(학습 설계 스튜디오)은 설계·검증 도구로 `/studio`에 남고 관리자만 들어간다.

학습자가 하는 일:
1. 아이디·비밀번호로 가입한다. 개인정보 수집·이용 동의가 필수이고, 이메일·연락처·연령·성별·소득은 받지 않는다.
2. 투자 목적·기간·위험성향·경험·관심 주제(최대 2개)를 고른다.
3. 진단 퀴즈 20문항을 푼다. 맞힌 단원은 이미 아는 단원으로 보고 추천에서 뺀다. 그 가운데 아직 모르는 단원은 체크해서 다시 추천받을 수 있다.
4. 홈에서 로드맵 진행률과 지금 공부할 단원 5개를 본다. 추천 이유는 쉬운 말로 보여 주고, 점수 근거는 ‘추천 근거 자세히’에 둔다. 하루 한 번 ‘추천 이유가 이해되나요?’(1~5)를 묻는다.
5. 단원에서 핵심 요점·예시·학습 자료 링크를 보고 학습 완료·저장·이해 확인을 한다.
   - 66개 단원 모두 학습 요점과 이해 확인 문항이 있다(`etfrec/lessons.py`·`lessons_core.py`, `etfrec/unit_checks.py`).
   - 확인 문항은 진단 퀴즈와 따로 둔 계산·적용형이고, 정답 위치를 고르게 섞었다.
   - 확인 문항이 없는 단원(구버전 카탈로그 등)은 스스로 확인으로 따로 기록한다.
6. 로드맵, 목적별 ETF 유형 카드, 내 정보(정보 수정, 진단 다시 하기, 마무리 설문, 내 데이터 JSON 내려받기, 로그아웃, 계정 삭제)를 쓴다.

화면은 휴대폰에서 하단 탭, 데스크톱에서 상단 메뉴로 바뀐다.

운영 루프(`--ops-dir`)를 켜면 학습자 화면의 추천도 `/api/serve`처럼 마지막 칸을 탐색하고 노출 확률을 기록한다. 단원 열람·학습 완료·저장·이해 확인은 같은 주의 반응 기록이 된다. 기록의 학습자 번호는 가입 순서로 매긴 가명 번호(ref)이며 아이디는 남지 않는다. 주차는 서비스 시작 주의 월요일부터 센다.

파일럿 평가를 위해 저장하는 것:
- 실제로 보인 추천 목록(순서 그대로)과 추천 목록에서 연 단원
- 추천 이유 이해도
- 진단 면제 확인(되돌린 단원)
- 마무리 설문(1~5점 5문항과 자유 의견)

관리자는 `/?admin=1`로 로그인하면 열리는 관리자 메뉴(내 정보)에서 ‘파일럿 보고서 보기’, ‘분석 자료 내려받기(zip)’, ‘스튜디오 열기’를 쓴다.
- 보고서는 중간보고서 7절의 지표를 계산한다: 7일 이해 확인 통과율(Wilson 95% 구간), 이용 흐름, 과도한 면제, 이유 이해도, 후보 부족, 추천 반응, 마무리 설문.
- 실데이터 기법 비교도 함께 낸다. 추천 시점의 학습자 상태로 기법마다 Top-5를 다시 계산해 그 뒤 7일 안의 통과를 맞혔는지 보고, 구간은 참가자 단위 부트스트랩이다.
- 같은 보고서를 `web pilot-report --as-of YYYY-MM-DD` 명령으로도 만든다.

운영 일정, 모집 문구, 교육 검토자 평가 절차는 [`docs/pilot/README.md`](docs/pilot/README.md)에 있다.

**자체 서버에 배포하기(Docker + HTTPS):**
- 도메인 하나와 Docker가 설치된 Linux 서버가 필요하다. 도메인의 DNS가 서버를 가리키고 80·443 포트가 열려 있어야 Caddy가 인증서를 받는다.
- 저장소 폴더의 `.env`에 아래 값을 적고 실행한다. `.env`는 저장소에 올리지 않는다.
  - `DOMAIN=learn.example.com`
  - `ETFREC_ADMIN_PASSWORD=관리자비밀번호`
  - 초대받은 사람만 가입하게 하려면 `ETFREC_INVITE_CODE=수업코드`

```bash
docker compose up -d --build                                                       # https://도메인/ (첫 실행 약 1분)
docker compose exec app python -m etfrec web stats                                 # 상태 확인
```

- 번들, 계정 DB, 운영 기록은 모두 `runs` 볼륨(Render는 디스크)에 있다.
- 백업은 관리자 화면의 분석 자료 내려받기 또는 `docker compose exec -T app python -m etfrec web backup --out runs/web/backup-YYYYMMDD.db`로 한다.
- 앱은 root가 아닌 사용자로 돈다. 확인한 메모리 사용량은 약 170~210MB였다.

주간 작업(cron 예: 매주 월요일 03:20):

```cron
20 3 * * 1  cd /srv/forclaudekyoungho && docker compose exec -T app sh -c 'python -m etfrec web export-dataset --out runs/web/export && python -m etfrec ops run-week --ops-dir runs/ops --data runs/web/export' && docker compose restart app
```

1. `web export-dataset`은 끝난 주의 기록을 학습 형식(profiles·study_log·catalog CSV)으로 내보낸다.
   - 학습자 번호는 ref다.
   - 시각은 4개 시간대만 남기고, 일·분은 0으로 둔다.
   - 진단 퀴즈로 인정한 단원은 `source=diagnosis`로 표시한다. 특징에서는 통과 단원으로만 쓰고, 평가 정답과 활동 학습자 수에서는 뺀다.
2. `ops run-week`가 재학습·재선정·검증 게이트·이력 기록을 한다.
   - 확인 주와 선정 주 모두 활동 학습자가 200명 이상이어야 교체를 판정한다.
   - 그보다 적으면 ‘표본 부족’으로 이력만 남긴다. 탐색·노출 기록은 그동안에도 계속 쌓인다.
3. 정책 교체는 실행 중인 서버가 바로 반영한다. 새 서빙 번들은 재시작해야 읽으므로 끝에 `restart`를 둔다.

보안·개인정보 장치:

| 항목 | 내용 |
| --- | --- |
| 비밀번호·세션 | 비밀번호는 scrypt 해시로만 저장한다. 세션 쿠키는 HttpOnly·SameSite=Lax이고, HTTPS에서는 Secure를 붙인다. 14일 동안 쓰지 않으면 만료되고, 비밀번호를 바꾸면 기존 세션이 끊긴다 |
| 요청 위조 방지 | 상태를 바꾸는 요청은 같은 화면이 붙이는 `X-Requested-With` 머리글이 있어야 처리한다 |
| 시도 횟수 제한 | 로그인 실패는 아이디별 15분에 8회까지다. 강의실처럼 여러 사람이 같은 공인 IP를 쓰는 경우를 고려해 IP별로는 넉넉히 둔다(실패 15분에 100회, 가입 시간당 60회). 프록시 뒤에서는 앞단이 채운 실제 접속 주소를 쓴다 |
| 보안 헤더 | CSP(같은 출처 스크립트만), 프레임 금지, nosniff, HSTS(HTTPS), API 응답 캐시 금지 |
| 관리자 경로 | 공개 모드에서는 스튜디오·평가·운영·미리보기 API를 관리자 세션만 쓴다. 모의 학습자 표 조회는 관리자에게도 닫는다 |
| 데이터 최소화·삭제 | 연령·성별·소득·연락처는 받지 않는다. 탈퇴하면 계정, 학습 기록, 해당 학습자의 노출·반응 기록을 바로 지운다. 내 데이터는 JSON으로 내려받을 수 있다 |
| 관리 명령 | `web create-admin`, `reset-password`, `revoke-admin`, `export-dataset`, `backup`, `pilot-report`, `bootstrap`, `stats`. 비밀번호는 환경변수 `ETFREC_ADMIN_PASSWORD` 또는 입력 창으로만 받는다 |
| 분석 자료 | 관리자 보고서·zip에는 가명 번호(ref)만 나오고 아이디·비밀번호 해시는 들어가지 않는다 |

실사용 전에 알아 둘 한계:
- **모델**: 추천 모델은 모의 데이터로 학습되어 있다(화면 아래에 고지). 실제 효과는 파일럿 기록이 쌓인 뒤 주간 작업과 별도 평가로 확인해야 한다.
- **비밀번호 분실**: 이메일을 받지 않으므로 자동 재설정이 없다. 관리자가 `web reset-password`로 바꿔 준다.
- **규모**: 시도 횟수 제한은 프로세스 메모리에 있어 서버 프로세스 1개 기준이고, 재시작하면 초기화된다. 저장소는 SQLite 파일 하나라 수업·파일럿 규모(수백~수천 명)를 전제로 한다.
- **OPE 일치도**: 서빙은 그 순간까지의 기록을 모두 쓰지만, 주간 평가는 주가 시작되기 전 기록으로 스냅샷을 만든다. 그래서 웹 학습자에 대한 기록 정책 일치도가 모의 실행보다 낮을 수 있다. 0.95 미만이면 OPE는 판정에 쓰지 않는다.
- **운영 기관의 몫**: 개인정보 처리방침과 이용약관의 법적 검토, 운영 주체 표시, 보관 기간은 운영 기관이 정해야 한다. 동의 문구는 출발점이다.

## 확인 범위와 한계

- 확인 환경: Linux, Python 3.13, NumPy 2.5, pandas 3.0, scikit-learn 1.9, FastAPI 0.115. 이전 기록 환경(Python 3.12, NumPy 2.3.5, pandas 2.2.3)과 보고서 수치가 같다.
- torch가 없는 환경에서 확인했다. 원래의 torch MF·MLP 학습 경로와 이를 쓰는 테스트는 실행하지 않았고, MF·MLP 비교는 NumPy 구현(`etfrec/factor_models.py`)으로 했다. torch 경로를 쓰려면 torch를 설치한 뒤 `--no-neural` 없이 학습한다. torch 경로의 테스트는 torch가 있는 환경에서 따로 실행해 통과했다(위 ‘테스트’).
- `python -m etfrec serve`로 띄운 서버에서 API 응답(상태, 진단 20문항, 신규 사용자 추천)과 화면 로드를 확인했고 브라우저 오류는 없었다. 실제 사용자의 사용성은 확인하지 않았다.
- 공개 모드는 2026-10-26에 Docker 이미지를 빌드해 Caddy(HTTPS) 뒤에서 띄운 뒤 확인했다.
  - 브라우저(휴대폰 390px·데스크톱 1280px)로 가입, 목적 입력, 진단, 추천, 단원 이해 확인, 재로그인 후 기록 유지, 관리자 스튜디오 진입까지 오류 없이 동작했다.
  - 컨테이너 안에서 번들 학습(15,000명, 약 1분), 운영 등록부 생성, 관리자 생성, 데이터 내보내기, 백업 명령을 실행했다.
  - 실제 도메인의 공인 인증서 발급은 이 환경에서 확인하지 못했다. Caddy 내부 인증서(localhost)로만 확인했다.
- 윈도우 데스크탑 운영은 실제 윈도우 기기에서 돌려 보지 않았다. 대신 리눅스에서 윈도우에서 깨지기 쉬운 지점을 재현해 확인했다(2026-10-26).
  - 인코딩: 파일 기본 인코딩을 ASCII로 강제한(한글 윈도우 cp949보다 엄격한) 상태에서 첫 실행 준비·서버·학습자 흐름·내보내기·보고서·백업·데스크탑 실행 도우미를 돌렸다.
  - 인코딩 누락 검사: 인코딩을 지정하지 않은 파일 열기를 경고하는 모드로 전체 테스트를 돌리고, 코드 구조 분석으로도 한 번 더 찾았다.
  - 새 설치: 최신 패키지를 새로 설치한 가상환경에서 전체 테스트를 돌렸다.
  - 줄바꿈: 저장소 줄바꿈을 LF로 고정했다(`.gitattributes`, `.bat`만 CRLF).
  - `start-windows.bat`의 설치·재설치 판단은 같은 로직의 맥·리눅스용 시작 파일을 실제로 돌려 확인했다.
- KRX·공공데이터포털 시세 연결은 인증키가 필요하다. 테스트는 가짜 응답으로만 확인한다.
- 모든 결과는 모의 데이터에서 얻었다. 실제 학습 효과와 진단의 타당성은 파일럿 자료로 평가한다.
- 자체 진단·퀴즈는 금융투자교육원의 레버리지 상품 사전교육이나 증권사 거래 요건을 대신하지 않는다.
