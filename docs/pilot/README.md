# 11월 파일럿 운영 안내

중간보고서 7절에서 약속한 실사용 검증을 실제로 수행하기 위한 안내다. 기말보고서의 데이터 확보, 실데이터 기법 비교, 평가 계획 실행이 이 파일럿의 기록에서 나온다.

중간보고서의 약속:
- 11월 1주에 단원·문항·출처와 운영 정책을 동결한다.
- 11월 2~3주에 목표 20명의 동의를 받아 진단과 추천·학습을 기록한다.
- 11월 4주에 이수 인정의 과도한 면제, 설명의 이해 가능성, 후보 부족을 검토한다.
- 참가자 가운데 7일 안에 학습 후 퀴즈를 하나 이상 통과한 비율을 관측한다.
- 파일럿 전에 목적·선행 지식만 제시한 사례를 교육 검토자에게 독립적으로 평가받는다.
- 실제 파일럿 기록에서의 기법 비교를 기말보고서에 포함한다.

| 12월 | | 기말보고서 반영, 서비스 종료와 자료 파기 |

## 1. 교육 검토자 평가와 동결 (11월 1주)

1. `expert_review_cases.md`(읽기용)와 `expert_review_cases.csv`(평가 입력용)를 검토자 1~2명에게 보낸다.
   - 사례는 투자 목적 5개 × 선행 지식 3단계 = 15개다.
   - 검토자는 서로 상의하지 않고 단원마다 적절성(1~5), 순서 문제(O/X), 빠진 필수 단원, 의견을 적는다.
2. 돌려받은 CSV를 요약한다.
   ```bash
   python scripts/expert_review_packet.py --summarize 검토자A.csv 검토자B.csv --out results/pilot
   ```
   사례별 평균 적절성, 순서 문제 비율, 검토자 간 일치도, 의견이 `results/pilot/expert_review_summary.md`에 정리된다.
3. 심각한 문제가 있을 때만 로드맵을 고친다. 고쳤으면 평가지를 다시 만들어 함께 기록한다.
   ```bash
   python scripts/expert_review_packet.py --bundle runs/seed42 --out docs/pilot
   ```
4. 배포한 커밋에 태그를 붙여 동결한다(`git tag pilot-freeze-2026-11`). 이후 파일럿이 끝날 때까지 단원·문항·운영 정책을 바꾸지 않는다.
   - 운영 루프가 켜져 있어도 주당 활동 학습자가 200명이 안 되면 정책은 바뀌지 않는다(‘표본 부족’으로 기록).
   - 서빙 번들 정보(모의 학습자 수, 생성 시각)는 파일럿 보고서 7절에 찍힌다.

## 2. 배포

저장소 README의 ‘웹 서비스로 운영하기’를 따른다.

- **Render(권장)**
  - New → Blueprint에서 이 저장소와 브랜치를 고른다.
  - 관리자 비밀번호와 초대 코드를 입력한다.
  - 첫 배포 때 번들 학습, 운영 등록부, 관리자 계정이 자동으로 준비된다.
  - 디스크가 필요해 starter 플랜(유료)을 쓴다.
- **자체 서버**: `.env`에 도메인과 관리자 비밀번호를 적고 `docker compose up -d`를 실행한다.

참가자만 가입하도록 **초대 코드를 꼭 설정한다.** 마지막 추천 칸은 10% 확률로 다른 후보로 바뀐다(탐색). 동의 문구에 이 내용이 있다.

리허설(2~3명) 때 확인할 것:
- 가입 → 목적 입력 → 진단 → 면제 확인 → 추천 → 단원 학습·이해 확인 → 추천 이유 평가 → 마무리 설문이 끝까지 되는가
- 관리자 계정으로 `/?admin=1`에 로그인하면 관리자 메뉴(내 정보)가 열린다. ‘파일럿 보고서 보기’에 기록이 잡히는가
- 리허설 계정은 파일럿 전에 각자 내 정보 → 계정 삭제로 지운다

## 3. 참가자 모집과 안내

모집 대상은 ETF 투자를 공부하고 싶은 성인(수강생, 지인 등)이고 목표는 20명이다. 이름·연락처는 서비스에 넣지 않는다. 모집 연락처는 서비스 밖에서 관리하고 파일럿이 끝나면 지운다.

모집 문구 예시:

> ETF 교육 콘텐츠 추천 서비스 파일럿 참가자를 모집합니다. 투자 목적과 진단 퀴즈 결과로 지금 공부할 ETF 단원을 추천하는 수업 프로젝트입니다. 11월 9일~22일 중 7일 동안 하루 5~10분 사용하고 마지막에 1분 설문에 답해 주시면 됩니다. 아이디·비밀번호 외에 이름·연락처·나이·소득은 받지 않으며, 언제든 계정을 삭제하면 기록이 바로 지워집니다. 특정 상품의 매수·매도를 권유하지 않습니다.

참가 안내(참가자에게 보낼 메시지):

1. 주소에 접속해 회원가입한다(초대 코드 입력, 개인정보 수집·이용 동의).
2. 투자 목적·기간·위험성향·경험을 고른다.
3. 진단 퀴즈를 푼다. 이미 아는 단원으로 처리된 것 가운데 아직 모르는 단원이 있으면 체크한다.
4. 7일 동안 하루 5~10분, 홈의 추천 단원을 학습하고 ‘이해 확인’을 푼다. ‘추천 이유가 이해되나요?’ 질문에도 답한다.
5. 7일이 지나면 내 정보 → 마무리 설문에 답한다.
6. 그만두고 싶으면 내 정보 → 계정 삭제를 누른다. 기록이 바로 지워진다.

## 4. 운영 중 점검 (매일 1분)

- 관리자 내 정보 → ‘파일럿 보고서 보기’의 1절(이용 흐름)에서 막힌 단계를 확인한다. 예: 진단에서 많이 멈추면 안내를 보낸다.
- 비밀번호를 잊은 참가자는 관리자가 바꿔 준다.
  - Render: Shell 탭
  - 자체 서버: `docker compose exec app python -m etfrec web reset-password --username 아이디` (비밀번호는 입력 창으로)
- 백업은 주 2회 한다.
  - 관리자 화면 ‘분석 자료 내려받기(zip)’
  - 또는 `docker compose exec -T app python -m etfrec web backup --out runs/web/backup-날짜.db`

## 7. 해석 원칙 (미리 정해 둔다)

- **주 지표**: 하나(7일 이해 확인 통과율, 문항 정답 기준)다. 스스로 확인을 포함한 비율과 나머지 지표는 탐색적으로만 본다.
- **유의성**: 20명 규모의 편의표본이므로 비율은 95% 구간과 함께 보고하고 유의성을 주장하지 않는다. A/B 효과 검증은 군당 수천 명이 필요한 후속 과제다(보고서 표 12).
- **기법 비교의 편향**: 참가자가 실제로 본 목록은 운영 정책이므로, 다른 기법이 고른 단원은 덜 노출되었다(노출 편향). 결과는 순위 비교의 참고 자료로만 쓴다.
- **자료 구분**: 모의 데이터 결과와 실사용 결과를 섞지 않고 구분해 보고한다.
- **계획 변경**: 계획을 바꾸면 날짜와 이유를 기록한다.

## 8. 파일럿 뒤 자료 처리

- 기말보고서 제출 뒤 서비스를 종료한다. 계정 DB와 백업은 정한 날짜(예: 2027년 1월 31일)에 지운다.
- 모집 때 이 일정을 참가자에게 알린다.
- 보고서에는 집계 결과와 가명 번호 수준의 표만 싣는다.
- 수업 과제 범위를 넘어 학술 연구로 확장하면 소속 기관의 연구윤리(IRB) 절차를 확인한다.
